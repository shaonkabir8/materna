02 · Capabilities

✦ Features

Everything a locale-parity test suite needs — nothing it doesn't.

⚙

Zero-config probing

npx materna node works instantly — no config file, no init step.

🌐

Database & runtime parity

Natively probes Node.js Intl.Collator and PostgreSQL ORDER BY against the same corpus.

📄

Deterministic HTML reports

materna report.html emits reviewable, diffable HTML with zero JavaScript inside.

🔬

E3/E1 evidence levels

Clearly separates "executed here" from "configured in CI" — no ambiguity in the report.

🚦

Strict exit codes

CI-friendly: 0=PASS, 1=DIFFERENCE, 2=INCONCLUSIVE, 3=ERROR.

🔗

Tie-structure aware

Detects subtle differences in equality groups, not just ordering — where collation bugs hide.

📦

Single runtime dependency

pg is dynamically imported — import 'materna' loads no database driver.

🔒

Zero hosted control plane

Runs entirely on your machine or CI. No SaaS, no telemetry, no account.

🧬

Immutable corpus

Samples are hashed and verified. Tampering is refused — every verdict is reproducible.

03 · Examples

⌨ Usage

Two entry points for the same engine. Expand one, copy the snippet.

terminal 
# Probe Node.js runtime
npx materna node --json > node.json

# Probe PostgreSQL (DATABASE_URL is honored)
DATABASE_URL='postgresql://postgres:postgres@localhost:5432/localeparity' \
  npx materna postgres --json > pg.json

# Compare the two observations
npx materna compare --left node.json --right pg.json
index.mjs 
import { probeNode, probePostgres, compareObservations } from 'materna';

const left = probeNode({ locale: 'de-DE' });
const right = await probePostgres({
  locale: 'de-DE',
  connectionString: process.env.DATABASE_URL,
});

const outcome = compareObservations(left, right);

if (outcome.status === 'DIFFERENCE') {
  // inspect outcome.first_difference for the exact index
}
03 · Reference

ƒ probeNode(options)

Synchronously returns an observation of Node.js Intl.Collator behavior. Works in Node, Bun, and Deno.

OptionTypeDescription
localestringBCP 47 locale tag, e.g. 'de-DE'.
sensitivitystring'base', 'accent', 'case', or 'variant'.
numericbooleanEnable numeric collation.
corpusarrayOptional custom corpus. Defaults to the immutable built-in corpus.
✓
Return value. A collation observation object. The fingerprint is a SHA-256 digest over the sorted corpus — every byte is auditable.
03.1 · Reference

ƒ probePostgres(options)

Asynchronously probes PostgreSQL ORDER BY behavior. Requires a live connection.

OptionTypeDescription
connectionStringstringPostgreSQL connection URL. Honored from DATABASE_URL in the CLI.
localestringBCP 47 locale tag, e.g. 'de-DE'.
⚠
No silent fallback. If the connection fails, probePostgres throws. The caller decides whether to skip or fail — no hidden retry, no empty result.
03.2 · Reference

ƒ compareObservations(left, right, [opts])

Compares two observations and returns a single outcome object.

FieldTypeDescription
statusstring'PASS', 'DIFFERENCE', or 'INCONCLUSIVE'.
first_differenceobjectExact index and values where the two orderings diverge. Present only when status is DIFFERENCE.
metadata_differencesarrayEnvironment differences (e.g. ICU version) that do not cause a failure.
✓
INCONCLUSIVE is not a failure. When either observation is null or missing, the comparison aborts safely with exit code 2. Nothing is proven either way.

05 · Compatibility

⇄ Compatibility & why materna

Versions are metadata. Observed behavior is evidence. materna declares a mismatch only when two runs over the same declared probe and corpus produce different observed orderings.

Why materna?

The Old Way (Version Metadata) The New Way (Behavioral Evidence)
You check process.versions.icu === '78.3' and assume compatibility. You run probeNode() and probePostgres(), then compare their actual observed orderings.
An ICU or glibc update silently breaks sorting. materna fingerprints the actual collation output with SHA-256.
You find out in production when ORDER BY mismatches. You find out in your test suite, with a precise first_difference.
"We use PostgreSQL 16 and Node 22, so it should be fine." "We proved the exact de-DE corpus produces identical orderings and tie structures."

Notes

  • Node.js ≥ 22 is required for the CLI.
  • PostgreSQL is optional — only needed for materna postgres.
  • The corpus is immutable. Samples are hashed and verified; tampering is refused.
  • Exit codes are strict and CI-friendly: 0=PASS, 1=DIFFERENCE, 2=INCONCLUSIVE, 3=ERROR.
